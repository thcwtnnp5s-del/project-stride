# Pixel UI content — v1

Provenance and native sizes for every file in this directory. Declared file by
file in `pubspec.yaml`; an undeclared file here is an asset that does not exist.

Every one is drawn through `lib/ui/components/pixel_asset.dart`, at an exact
integer multiple of the native size below, with nearest-neighbour filtering and
no smoothing (`ART_DIRECTION.md` **L-18**). **The native size is declared in the
widget, not encoded in the filename**, and there are deliberately no `2.0x/` or
`3.0x/` variant directories.

## The one file that needs explaining

### `nav_world_hi.png` — derived, not authored

The other three active variants came from `gen_assets.js`, which cannot run here
— it requires `pngjs`, and nothing in this repository installs it. Enabling the
World tab needed a fourth.

`Scripts/art/nav-active-variant.js` recovers the transform instead of inventing
one. Every `nav_*.png` shares a single master palette, and each `_hi` file has a
**byte-identical `PLTE`** to its base: the active variant recolours by pointing
each pixel at a brighter entry of the same palette. That makes the difference an
index→index remap, and reading it off the three existing pairs gives the mapping
directly. Two indices are remapped, none contested, none unseen.

So the fourth glyph brightens exactly as the other three do, rather than by a
brightness rule made up for it.

## Game art is not here

Item icons, the portrait, sprites, animation, the region map and the location
vignette moved to **`assets/art/v1/`** when the PixelLab family replaced the
code-rendered set. This directory is interface chrome only.

The predecessor item icons and portrait were removed rather than kept beside the
new ones: a second icon set that nothing renders is a set someone will
eventually render by accident. Their history is in git, and the reasoning that
retired them is in `assets/art/v1/README.md`.
