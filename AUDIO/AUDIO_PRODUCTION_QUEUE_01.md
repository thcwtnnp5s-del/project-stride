## 1. How to run this queue

### 1.1 Preflight — every item is a stop condition

1. **The owner has reopened generation, in writing.** Without that, stop here.
2. `STABILITY_API_KEY` exported in the shell. Never logged, never echoed, never
   committed. `gen2.mjs` reads it from the environment only.
3. `node` available.
4. **Read the live balance and write it down** before anything else:
   `GET https://api.stability.ai/v1/user/balance`, `Accept: application/json`.
   Record it in the workstream index with the date. **Never trust a remembered
   figure** — including the 61 in this document.
5. Create the workstream tree, mirroring AP1:
   `AUDIO/evaluation/<workstream>/{tools,provenance,<cue>/raw,<cue>/listening}`.
6. Confirm the seed you are about to use is not in §0's consumed list and is
   not a seed the owner ruled dead (§1.5).

### 1.2 Transport rules — these are paid-for lessons

- **`Accept: audio/*` on the generate call. Never `Accept: application/json`.**
  Six SA3 calls with the JSON transport returned HTTP 500 `internal_shape` with
  no audio and **burned 156 credits** (bake-off 00 INDEX, round facts). That is
  more than two and a half times the entire recorded balance.
- **Fire one call, verify, then fire the batch.** The 156-credit loss happened
  because six calls went out before anyone looked at a result. For any cue
  category not previously generated, roll **one** candidate, confirm
  `finish_reason == SUCCESS`, non-trivial `bytes`, and that the file is audible,
  and only then queue siblings.
- **Per-call balance reads lag and are erratic.** Every AP1 provenance file
  records this. Settle the true cost by a balance read **before the batch** and
  **after the batch**, then divide. Record it as `credit_cost_settled`.
- One job JSON per generation, kept beside the run, exactly as AP1 did:

```json
{
  "id": "VICTORY_PCE1_SA25_7101",
  "family": "sa25",
  "prompt": "<verbatim prompt from this document, unmodified>",
  "seed": 7101,
  "duration": 4,
  "output_format": "wav",
  "provDir": "provenance",
  "outDir": "victory/raw"
}
```

`family` is `sa25` (stable-audio-2.5) or `sa3` (stable-audio-3). `steps` and
`cfg_scale` are omitted for SFX — **model defaults**. The house cfg 4 / steps 8
baseline is the SA3 **music** baseline and has never been an SFX ruling
(`INDEX_MINING.md`).

### 1.3 After every generation, before any listening

1. **Never audition a raw.** The provider returns peak-normalized files with
   true peaks *above* full scale (+2.1 to +4.3 dBTP across the recorded set).
   Make a listening copy: gain to exactly **−1.0 dBTP**, no other processing.
2. Measure on the listening copy and write into the provenance JSON:
   duration, codec, sample peak, true peak, integrated LUFS, **LUFS-M max**
   (400 ms momentary maximum), and a one-line decay/profile description in the
   style AP1 used.
3. Apply the **measurement gate** (§1.4) *before* the owner's ear. A take that
   fails measurement never reaches a listening pass.

Reference commands (deterministic, recordable):

```
# true peak + integrated, and per-frame momentary values to parse for LUFS-M max
ffmpeg -i CAND.wav -af ebur128=peak=true:framelog=verbose -f null -
# listening copy / packaging gain (g = -1.0 - measured_true_peak_dbtp)
ffmpeg -i CAND.wav -af "volume=<g>dB" -c:a pcm_s16le -ar 44100 CAND_LISTENING.wav
```

### 1.4 The measurement gate — produce hot, ship trimmed

This is the rule mining's predicament exists to teach. **The runtime can only
attenuate.** `ActionCue.trimDb` is documented as zero-or-negative and cannot be
positive. A cue that arrives quiet is unfixable without a re-master, and a
re-master of an accepted asset is an owner ruling. Therefore:

> **Never accept a quiet take.** Produce hot and trim down at runtime.

Gate, measured on the **−1.0 dBTP listening copy**:

| Class | Cues | Required LUFS-M max | Rejected on measurement alone |
|---|---|---|---|
| Impact / resolve | all `combat.impact.*`, `combat.brace.absorb.01`, `reward.*`, `craft.complete.*` | **≥ −16.0** | below −16.0 |
| Action / gesture | `combat.swing.*`, `combat.attack.*`, `combat.brace.01`, `craft.cooking.stir.01`, `gather.complete.01`, `ui.commit.01` | **≥ −18.5** | below −18.5 |
| Warning / arrival | `combat.telegraph.heavy.01`, `combat.encounter.begin.01`, `combat.heal.01` | **≥ −19.0** | below −19.0 |

The action-class floor of −18.5 is set deliberately just under shipped
woodcutting (−18.4, which reads acceptably) and above shipped mining (−20.4,
which does not). It would have caught mining at generation time for free.

**Open discrepancy, flagged not resolved:** the event matrix §3.2 proposes an
action-class target of **−13.0 LUFS-M max ±1.0**, while the shipped
implementation applies a **−17.0** ceiling (`assets/audio/v1/README.md`). Those
are two different numbers in two live documents. This queue produces *into the
gap* — hot enough to satisfy either, then trimmed down — so no generation is
wasted whichever way the owner rules. The number itself is an owner/DIR-D item
(§8).

### 1.5 Rerolls and dead seeds

- A cue owns a seed **block**: its base seed and the next two.
  `7101 → 7102 → 7103`. This mirrors mining (4101→4102) and cooking
  (4501→4502→4503). Blocks are spaced so no block can collide (§2.4).
- **A seed the owner has ruled dead is dead.** `COOK_AP1_SA25_4501` and `4502`
  carry explicit rulings: *"Do not derive from this file or reuse seed."* That
  is binding, and it is why 4503 exists.
- A reroll **rewrites the prompt** in the direction the rejection named. It does
  not re-fire the same prompt hoping for luck. Cooking's three rolls each moved
  the emphasis deliberately (utensil-led → simmer-led → sizzle-only) and only
  the third passed.
- **Every roll's provenance JSON is written before the file is judged.**

### 1.6 On acceptance

1. Owner listening pass on the −1.0 dBTP copy. Record the ruling verbatim in the
   provenance JSON (`acceptance` or `ruling`), as AP1 did.
2. Package deterministically — gain / trim / fade / format only:
   SFX → WAV 44.1 kHz 16-bit stereo, gain to −1.0 dBTP, head trim to 10 ms
   before the first sample above −60 dBFS, 10 ms in-fade / 120 ms out-fade,
   tail cut where the gesture has settled. Music → AAC 192 kbps m4a.
3. Add the row to `AUDIO/AUDIO_ASSET_MANIFEST.md` (asset ID, file, source with
   candidate ID and seed, licence, model, verbatim prompt, date, **Used by**).
4. Add the file row and packaging note to `assets/audio/v1/README.md`.
5. Add the `files` entry and the cue's `trimDb` in `lib/audio/audio_cues.dart`.
6. Rejected takes are **retained, never deleted**, with `REJECTED_REFERENCE`
   status and the owner's reason in the JSON.

## 2. Constraints that bind every brief in this document

### 2.1 The phone speaker

Project Stride is played on a phone speaker held at arm's length, usually with
region music under the cue. **Nothing below roughly 120 Hz survives that
transducer.** A cue whose weight lives in the sub is a cue that does not exist
on the device it ships to.

Therefore, written into each brief below rather than assumed:

- **Weight lives in the 200–600 Hz body**, and in the sharpness of the front
  transient. Never in low-end boost. A prompt that asks for "deep sub bass" or
  "earth-shaking rumble" is asking for silence.
- **The front transient is the whole event.** On a small speaker, the first
  30 ms is what makes a blow read as a blow. Prompts say *contact*, *knock*,
  *bite*, *tap* — never *swell*, never *whoosh into*.
- **Any tail longer than the duck release reads as a bell.** The music bus
  un-ducks on a fixed schedule (matrix §3.4): 700 ms after an impact, 900 ms
  after a resolve or telegraph, 1400 ms after a heavy impact or a major craft.
  A cue still sounding when the bed swells back is heard as ringing, not as
  weight. Each brief below states its own tail budget.
- **No reverb.** Every prompt says *dry close recording space*. Room tone
  competes with the music bed and smears the transient at phone bandwidth.

### 2.2 Duration policy — buy the longer file

stable-audio-2.5 costs **20 credits flat regardless of duration**. There is no
saving in requesting 1 s. There is a cost: the acceptance criteria below are
mostly *tail* measurements, and a 1 s file cannot evidence a 1400 ms tail claim.

**Rule:** request at least **twice the longest acceptance window** for the cue,
then trim deterministically in packaging. Most one-shots therefore move from the
matrix's 1 s to **2 s**. This is a production-side change; it alters no design.

**The known risk, and its escape hatch:** longer requests invite the model to
fill the time. `FORAGE_AP1_SA25_4302` and `4303` (2 s) both ended mid-motion;
`COOK_AP1_SA25_4502` (3 s) returned a sustained texture where a gesture was
wanted. Every one-shot brief therefore carries the reject condition *"exactly
one gesture, nothing after it."* **If two consecutive rolls come back filled,
drop that cue to 1 s for the third roll** — 1 s is what produced the accepted
mining, woodcutting and smithing takes.

### 2.3 House voice

Every prompt below is written to match `P-1`…`P-10` in
`AUDIO/AUDIO_ASSET_MANIFEST.md`: it opens with `TrackType:`, names the
**microphone position**, the **material**, the **decay**, and the **room**, and
ends by excluding what must not appear. Prompts are **verbatim** — copy them
character for character into the job JSON. A paraphrased prompt is an
unreproducible asset.

Prompts marked **(DIR-D, verbatim)** are reproduced unchanged from
`02_AUDIO_EVENT_MATRIX.md` §6. Prompts marked **(BUILD-E)** are authored here.

### 2.4 Seed allocation

Adopted unchanged from the matrix so the two documents cannot disagree:
combat SFX **6xxx**, reward/UI **7xxx**, new music **8xxx**, cooking stir
continues the cooking block at **4601**. Blocks verified this session against
every consumed seed in §0 — **no collisions**, including the +2 reroll range.

#### P0-1 · `reward.victory.01` — *"victory should resolve"*

Fires when the combat outcome layer rises with `outcome == won`, including the
skip path. Priority 90, duck −9 dB with a **1400 ms release**.
Model stable-audio-2.5 · 4 s · seed **7101** (rerolls 7102, 7103) · defaults · 20 credits.

Prompt **(DIR-D, verbatim)**:

```
TrackType: Music, VocalType: Instrumental. Short warm acoustic fantasy resolve for a small victory in an adventure RPG. Three or four rising plucked lute notes settle onto one warm sustained major chord from nylon-string guitar and soft felt piano, a breathy wooden flute holding a single note above it, warm low strings underneath; the phrase arrives, breathes and decays naturally into silence. Earned, satisfied, human warmth; a small triumph among friends, never a fanfare, never brass, never a jackpot or arcade flourish. Lo-fi production: warm tape saturation, rounded highs, soft even dynamics. Moderate tempo, one complete phrase, ending in quiet.
```

**Phone-speaker weighting.** The phrase must carry on plucked strings and felt
piano in the **250 Hz–2 kHz** band, which is where a phone speaker actually
lives. Low strings are colour, not foundation — if the chord's identity depends
on anything under 120 Hz, the cue is empty on the device.

**Tail budget.** The duck releases at 1400 ms after the cue length; the phrase
must be **complete and decaying by 3.5 s** so the bed swells back into quiet,
not into a still-ringing chord.

**Acceptance.** Heard over the Haven bed at music 0.55 on a phone speaker under
a −9 dB duck, the phrase reads as an **ending**, not a loop fragment. Measured
LUFS-M max ≥ −16.0.

**Reject if:** any brass; an ascending arpeggio ladder; a blind listener calls
it "a reward chime"; the phrase is cut off at 4 s; it sits so low in the mix
that it needs a boost to be heard (the runtime cannot boost); it is
indistinguishable in blind A/B from P1-6 `reward.levelup.01` or P1-7
`reward.milestone.01` once those exist.

**Until produced:** **SILENCE.** Nothing we own can stand in — see §4.

must not sound like iron, oak must not sound like pine, a mine must not sound
like a forest.* Those two rules collide, and this section is where the collision
is resolved cue by cue.

### 4.1 The three standing rules

1. **A placeholder must be materially honest.** Borrowing is allowed when the
   borrowed asset *is* the thing the new event depicts, in the same room, from
   the same work. It is forbidden when it would make one asset carry two
   different materials or two different meanings.
2. **Every placeholder use is recorded in the manifest's `Used by` column**,
   before it ships. That column exists so an asset's **blast radius is visible
   before it is replaced** — a re-master of `craft.smithing.01` that also serves
   a combat impact has to satisfy two masters, and nobody should discover that
   at re-master time.
3. **Every placeholder has an expiry.** The `Used by` row says which cue retires
   it (e.g. *"placeholder for `combat.impact.player.01` until seed 6101 is
   accepted"*). A placeholder without an expiry is a design decision made by
   omission, which `CLAUDE.md` forbids.

| `craft.complete.medium.01` | the crafting profession's own action cue, one terminal strike, at 0 dB under the −6 dB duck | The same hammer, the same anvil, the same work — the *last* blow instead of a middle one. No material is misrepresented. The tier difference is carried entirely by duck depth, so a Bronze Sword and a Herb Broth already resolve differently at zero credits. |
| `craft.complete.major.01` | as above, under the −9 dB duck | Same argument; deeper silence around the same strike reads as a bigger moment. |

The craft and gather completion placeholders are the strongest in the queue and

### 4.4 The one genuinely contested placeholder

`combat.impact.player.01` is P0 and, unlike the enemy impact, it has candidates.

**Option A — `craft.smithing.01` @ −2 dB** (the matrix's proposal). For: it is a
heavy metal tool striking with force, the same physical genus as a blade
landing, and the two contexts never share a screen. Against: it has a metallic
resonance that the cue's own brief explicitly forbids (*"no metallic ring, no
sustained blade tone"*), and it is the loudest asset we own (−10.0 LUFS-M max
before its −7.0 trim), so it will read as an anvil precisely because it is
unmistakable.

**Option B — `WOOD_AP1_SA25_4201`** (rejected woodcutting take, §5). For: a
blade sinking into an absorbing mass with the **deadest tail of the wood set**
(−94 dB by file end) and **no metallic ring at all** — it satisfies the brief's
central prohibition where Option A violates it. Against: it is a sibling take of
the shipped `gather.woodcutting.01` from the same prompt family; a player
chopping in Whispering Woods and fighting there would hear near-twins. It is
also `REJECTED_REFERENCE`, not an accepted asset, so adopting it re-opens a
closed gate and requires a manifest row of its own.

**Recommendation:** one blind listening pass, both options, on the phone, and
**silence if neither convinces**. Option B is the better sound and the worse
identity risk; Option A is the safer paperwork and the wrong material. If the
owner has no appetite for either, silence costs nothing and expires the moment
seed 6101 lands.
